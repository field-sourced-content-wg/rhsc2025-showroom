= モジュール 3: カスタムルールの追加
:source-highlighter: rouge
:toc: macro
:toclevels: 1

toc::[]

モジュール 2 では MTA と Konveyor AI による移行の流れを確認しました。しかし、あなたは一つのことが気になっています。「Spring Boot から Quarkus への移行では、起動クラス・MVC・JPA が核心なのに、チーム向けの具体的な手順がルールに載っていない。これでは移行がブレる。」

上司に報告したところ、返ってきた言葉はシンプルでした。「だったらルールを自分で作ればいい。」

MTA はカスタムルールをサポートしています。Spring Boot → Quarkus 向けの検出パターンを YAML で記述し、MTA に登録すれば、標準ルールと同じように分析に使えます。このモジュールでは、サンプルアプリ link:{app_2_gitrepo_url}[spring-petclinic^] を対象に、その仕組みを理解しカスタムルールを作成して登録します。

== 学習目標

このモジュールを完了すると、以下のことができるようになります:

* MTA のルールエンジンの構造 (when / message / tag) を説明できる
* YAML 形式でカスタムルールを作成できる
* 作成したカスタムルールを MTA に登録し、分析結果に反映できる

== エクササイズ 1: MTA ルールエンジンの仕組み理解

カスタムルールを作る前に、MTA がどのようにルールを処理するかを理解します。Spring Boot → Quarkus の移行ルールを正確に記述するには、ルールの構造を把握しておくことが大切です。

=== 前提条件

* 「環境の準備」で Dev Spaces ワークスペース（spring-petclinic）が起動していること
* MTA API に `{mta_admin_username}` / `{mta_admin_password}` でアクセスできること

=== MTA 組み込みルールセットの確認

MTA には各種移行に必要なルールがあらかじめ用意されています。まず、どのようなルールが組み込まれているかを確認します。

[source,bash,role="execute",subs="attributes+"]

----
+
ルールセットの名前と ID が JSON 形式で返ってきます。

=== ルールの YAML 構造を理解する

MTA のカスタムルールは YAML 形式で記述します。基本的な構造を確認します。標準的なルールの例を見てみましょう:

[source,yaml]
----
- ruleID: java-spring-boot-application-annotation
  labels:
    - konveyor.io/source=springboot
    - konveyor.io/target=quarkus
  message: |-
    `@SpringBootApplication` は Spring Boot 専用です。Quarkus では多くの場合起動クラスごと不要です。
    詳細: https://quarkus.io/guides/lifecycle
  tag:
    - SpringBoot
    - Quarkus
  when:
    java.referenced:
      pattern: org.springframework.boot.autoconfigure.SpringBootApplication
      location: ANNOTATION
----

各フィールドの役割を確認します:

[source,text]
----
ruleID   : ルールの一意識別子 (プレフィックスで分類すると管理しやすい)
labels   : 変換元/変換先のテクノロジーラベル
message  : 検出時に IDE / レポートに表示されるメッセージ
tag      : 検出結果を分類するタグ (フィルタリングに使用)
when     : 検出条件 (java.referenced / xml / filecontent など)
----

=== よく使う `when` 条件のパターン

[source,yaml]
----
# Java クラス・アノテーションを検出
when:
  java.referenced:
    pattern: org.springframework.stereotype.Controller
    location: ANNOTATION

# pom.xml の要素を検出
when:
  builtin.xml:
    xpath: /m:project/m:parent[m:artifactId='spring-boot-starter-parent']
    namespaces:
      m: http://maven.apache.org/POM/4.0.0
    filepaths:
      - pom.xml

# ファイル内の文字列パターンを検出
when:
  filecontent:
    pattern: "SpringApplication\\.run"
    filePattern: "*.java"
----

=== 確認

ルール構造を理解できたか確認します。次のコマンドを実行し、組み込みルールセットを一覧します:

[source,bash,role="execute",subs="attributes+"]
----
curl -s -u {mta_admin_username}:{mta_admin_password} {mta_ui_internal_url}/hub/rulesets | python3 -c "
import json, sys
data = json.load(sys.stdin)
print('取得したルールセット数:', len(data))
print()
print('各ルールセットの名前:')
for rs in data:
    name = rs.get('name', '名前なし')
    rs_id = rs.get('id', '?')
    print(f'  ID={rs_id}: {name}')
"
----

ルールセットの一覧が表示されれば、ルールエンジンへのアクセスは正常です。

== エクササイズ 2: カスタムルールの作成

PetClinic の Spring Boot → Quarkus 移行では、次の 4 点が特に重要です:

* 起動クラス: `@SpringBootApplication`
* Web 層: `@Controller` (Spring MVC → JAX-RS)
* HTTP マッピング: `@GetMapping` など
* データ層: `JpaRepository` (→ Panache)

これらを検出するカスタムルールセットを YAML で作成します。

=== 前提条件

* 「環境の準備」で spring-petclinic のワークスペースが起動していること
* エクササイズ 1 で MTA ルールの構造を理解していること
* Dev Spaces のターミナルが開いていること

=== カスタムルールファイルの作成

. 作業ディレクトリに移動し、カスタムルール用ディレクトリを作成します:
+
[source,bash,role="execute"]
----
mkdir -p ~/petclinic-custom-rules
cd ~/petclinic-custom-rules
----

. PetClinic 向け Spring Boot → Quarkus カスタムルールファイルを作成します:
+
[source,bash,role="execute"]
----
cat > ~/petclinic-custom-rules/spring-to-quarkus-rules.yaml << 'EOF'
- ruleID: java-spring-boot-application-annotation
  category: mandatory
  effort: 2
  labels:
    - konveyor.io/source=springboot
    - konveyor.io/target=quarkus
  description: "@SpringBootApplication は Quarkus では不要です。"
  message: |-
    `@SpringBootApplication` は Spring Boot 専用です。Quarkus では次のように整理します。

    1. 多くの場合は起動クラスごと削除し、CDI + `application.properties` だけで動かす
    2. 明示的な `main` が必要なら `@QuarkusMain` と `Quarkus.run(...)` を使う
    3. `SpringApplication.run(...)` は削除する
  tag:
    - SpringBoot
    - Application
    - Migration-Required
  when:
    java.referenced:
      pattern: org.springframework.boot.autoconfigure.SpringBootApplication
      location: ANNOTATION

- ruleID: java-spring-mvc-controller-to-jaxrs
  category: mandatory
  effort: 5
  labels:
    - konveyor.io/source=springboot
    - konveyor.io/target=quarkus
  description: "@Controller (Spring MVC) を JAX-RS リソースクラスに変換してください。"
  message: |-
    `@Controller` は Spring MVC 用です。Quarkus では JAX-RS リソースとして定義します。

    1. クラスに `@Path("/...")` と `@ApplicationScoped` を付与
    2. メソッドに `@GET` / `@POST` などを付与
    3. Thymeleaf 連携は Qute (`TemplateInstance`) へ移行

    影響例 (PetClinic): OwnerController, PetController, VisitController, VetController
  tag:
    - SpringMVC
    - JAX-RS
    - Migration-Required
  when:
    java.referenced:
      pattern: org.springframework.stereotype.Controller
      location: ANNOTATION

- ruleID: java-spring-getmapping-to-jaxrs-get
  category: mandatory
  effort: 3
  labels:
    - konveyor.io/source=springboot
    - konveyor.io/target=quarkus
  description: Spring MVC の @GetMapping 等を JAX-RS の @GET @Path 等へ置き換える
  message: |-
    Spring MVC の HTTP マッピングを JAX-RS に置き換えます。

    1. `@GetMapping("x")` → `@GET` + `@Path("x")`
    2. `@PostMapping` → `@POST` + `@Path` (同様に Put / Delete)
    3. 戻り値は論理ビュー名 (String) ではなく `TemplateInstance` または `Response`
  tag:
    - SpringMVC
    - JAX-RS
    - Migration-Required
  when:
    java.referenced:
      pattern: org.springframework.web.bind.annotation.GetMapping
      location: ANNOTATION

- ruleID: java-spring-jpa-repository-to-panache
  category: mandatory
  effort: 4
  labels:
    - konveyor.io/source=springboot
    - konveyor.io/target=quarkus
  description: JpaRepository インターフェースを Quarkus Panache に変換してください。
  message: |-
    `JpaRepository<Entity, Id>` は Spring Data のインターフェースです。

    1. `@ApplicationScoped` なクラスで `PanacheRepositoryBase<Entity, Id>` を実装する
    2. ID 型はエンティティの `@Id` に合わせる (PetClinic は `Integer` が多い)
    3. `repository.save(...)` は `persist(...)` / `persistAndFlush(...)` に置き換える

    影響例: OwnerRepository, PetTypeRepository, VetRepository
  tag:
    - SpringData
    - Panache
    - Migration-Required
  when:
    java.referenced:
      pattern: org.springframework.data.jpa.repository.JpaRepository
      location: IMPORT
EOF
----

. 作成したルールファイルを確認します:
+
[source,bash,role="execute"]
----
cat ~/petclinic-custom-rules/spring-to-quarkus-rules.yaml
----

. コンテナイメージには PyYAML が入っていないため、先にインストールします:
+
[source,bash,role="execute"]
----
python3 -m pip install --user pyyaml
----
+
`Successfully installed` または `Requirement already satisfied` と表示されれば完了です。

. YAML の構文が正しいことを確認します:
+
[source,bash,role="execute"]
----
python3 << 'PY'
import sys
import site
from pathlib import Path

# Dev Spaces では user site が sys.path に入らないことがある
user_site = site.getusersitepackages()
if user_site not in sys.path:
    sys.path.insert(0, user_site)

import yaml

with open(Path.home() / "petclinic-custom-rules/spring-to-quarkus-rules.yaml") as f:
    rules = yaml.safe_load(f)

print("ルール数:", len(rules))
for r in rules:
    print("  - {}: タグ {}".format(r["ruleID"], r.get("tag", [])))
PY
----
+
4 件のルールが表示されれば、YAML 構文は正しいです。

== エクササイズ 3: カスタムルールの適用と検証

カスタムルールファイルができました。次は MTA に登録し、サンプルアプリ link:{app_2_gitrepo_url}[spring-petclinic^] の分析を再実行して、カスタムルールが正しく機能することを確認します。

=== カスタムルールセットの MTA への登録

MTA API を使ってカスタムルールセットを登録します。

. まず、カスタムルールセットを MTA Hub API で作成します:
+
[source,bash,role="execute",subs="attributes+"]
----
curl -s -X POST \
  -u {mta_admin_username}:{mta_admin_password} \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Spring PetClinic to Quarkus",
    "description": "Spring Boot → Quarkus 移行ルール（PetClinic 向け）"
  }' \
  {mta_ui_internal_url}/hub/rulesets | python3 -m json.tool
----
+
レスポンスに `"id"` フィールドが含まれていれば、ルールセットが作成されています。ID をメモしておきます。

. 作成したルールセットの ID を変数に格納します:
+
[source,bash,role="execute",subs="attributes+"]
----
RULESET_ID=$(curl -s -u {mta_admin_username}:{mta_admin_password} {mta_ui_internal_url}/hub/rulesets | \
  python3 -c "
import json, sys
data = json.load(sys.stdin)
for rs in data:
    if rs.get('name') == 'Spring PetClinic to Quarkus':
        print(rs['id'])
        break
")
echo "カスタムルールセット ID: $RULESET_ID"
----

. YAML ルールファイルをルールセットにアップロードします:
+
[source,bash,role="execute",subs="attributes+"]
----
curl -s -X POST \
  -u {mta_admin_username}:{mta_admin_password} \
  -F "file=@${HOME}/petclinic-custom-rules/spring-to-quarkus-rules.yaml" \
  {mta_ui_internal_url}/hub/rulesets/${RULESET_ID}/rules | python3 -m json.tool
----

. カスタムルールが登録されたことを確認します:
+
[source,bash,role="execute",subs="attributes+"]
----
curl -s -u {mta_admin_username}:{mta_admin_password} \
  {mta_ui_internal_url}/hub/rulesets/${RULESET_ID}/rules | python3 -c "
import json, sys
data = json.load(sys.stdin)
if isinstance(data, list):
    print(f'登録済みルール数: {len(data)}')
    for rule in data:
        print(f'  - {rule.get(\"ruleID\", \"?\")}')
else:
    print(json.dumps(data, ensure_ascii=False, indent=2))
"
----

=== カスタムルールを含む分析の再実行

登録したカスタムルールを使って、サンプルアプリ link:{app_2_gitrepo_url}[spring-petclinic^] を再分析します。

. このモジュールで使用するアプリケーション（`{app_2_gitrepo_url}`）の ID を確認します:
+
[source,bash,role="execute",subs="attributes+"]
----
curl -s -u {mta_admin_username}:{mta_admin_password} {mta_ui_internal_url}/hub/applications | python3 -c "
import json, sys
data = json.load(sys.stdin)
print(f'登録済みアプリ数: {len(data)}')
for app in data:
    print(f'  ID={app[\"id\"]}: {app[\"name\"]}')
"
----

. アプリケーション ID を変数に格納します (リストに表示された最初のアプリを使用):
+
[source,bash,role="execute",subs="attributes+"]
----
APP_ID=$(curl -s -u {mta_admin_username}:{mta_admin_password} {mta_ui_internal_url}/hub/applications | \
  python3 -c "import json, sys; data = json.load(sys.stdin); print(data[0]['id']) if data else print('')")
echo "分析対象アプリ ID: $APP_ID"
----

. カスタムルールセットを含む新しい分析タスクを作成します:
+
[source,bash,role="execute",subs="attributes+"]
----
RULESET_ID=$(curl -s -u {mta_admin_username}:{mta_admin_password} {mta_ui_internal_url}/hub/rulesets | \
  python3 -c "
import json, sys
data = json.load(sys.stdin)
for rs in data:
    if rs.get('name') == 'Spring PetClinic to Quarkus':
        print(rs['id'])
        break
")

curl -s -X POST \
  -u {mta_admin_username}:{mta_admin_password} \
  -H "Content-Type: application/json" \
  -d "{
    \"application\": {\"id\": ${APP_ID}},
    \"mode\": {
      \"binary\": false,
      \"withDeps\": false,
      \"artifact\": \"\"
    },
    \"rules\": {
      \"rulesets\": [{\"id\": ${RULESET_ID}}],
      \"targets\": [\"quarkus\"],
      \"sources\": [\"springboot\"]
    },
    \"scope\": {
      \"packages\": {
        \"included\": [],
        \"excluded\": []
      }
    }
  }" \
  {mta_ui_internal_url}/hub/tasks | python3 -m json.tool
----

. 分析タスクの ID を取得し、ステータスを監視します:
+
[source,bash,role="execute",subs="attributes+"]
----
TASK_ID=$(curl -s -u {mta_admin_username}:{mta_admin_password} {mta_ui_internal_url}/hub/tasks | \
  python3 -c "

== 学習成果チェックポイント

このモジュールで学んだ内容を振り返りましょう。
