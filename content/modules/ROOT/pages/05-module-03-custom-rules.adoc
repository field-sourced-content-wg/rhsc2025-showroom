= モジュール 3: カスタムルールの追加
:source-highlighter: rouge
:toc: macro
:toclevels: 1

toc::[]

モジュール 2 では MTA と Konveyor AI による移行の流れを確認しました。しかし、あなたは一つのことが気になっています。「Spring Boot から Quarkus への移行では、起動クラス・MVC・JPA が核心なのに、チーム向けの具体的な手順がルールに載っていない。これでは移行がブレる。」

上司に報告したところ、返ってきた言葉はシンプルでした。「だったらルールを自分で作ればいい。」

MTA はカスタムルールをサポートしています。Spring Boot → Quarkus 向けの検出パターンを YAML でローカルに記述し、Dev Spaces の MTA プラグイン（Analysis Profile の Set rules）に追加すれば、標準ルールと同じように分析に使えます。このモジュールでは、サンプルアプリ link:{app_2_gitrepo_url}[spring-petclinic^] を対象に、その仕組みを理解しカスタムルールを作成して解析に載せます。

== 学習目標

このモジュールを完了すると、以下のことができるようになります:

* MTA のルールエンジンの構造 (when / message / tag) を説明できる
* YAML 形式でカスタムルールを作成できる
* 作成したカスタムルールを MTA プラグインのプロファイルに追加し、分析結果に反映できる

== エクササイズ 1: MTA ルールエンジンの仕組み理解

カスタムルールを作る前に、MTA がどのようにルールを処理するかを理解します。Spring Boot → Quarkus の移行ルールを正確に記述するには、ルールの構造を把握しておくことが大切です。

=== 前提条件

* 「環境の準備」で Dev Spaces ワークスペース（spring-petclinic）が起動していること
* MTA API に `{mta_admin_username}` / `{mta_admin_password}` でアクセスできること

=== MTA 組み込みルールセットの確認

MTA には各種移行に必要なルールがあらかじめ用意されています。まず、どのようなルールが組み込まれているかを確認します。

. Dev Spaces のターミナルで、MTA API を使って利用可能なルールセットを一覧取得します:
+
[source,bash,role="execute",subs="attributes+"]
----
curl -s -u {mta_admin_username}:{mta_admin_password} {mta_ui_internal_url}/hub/rulesets | python3 -m json.tool | head -60
----
+
ルールセットの名前と ID が JSON 形式で返ってきます。

. 組み込みルールセットの数を確認します:
+
[source,bash,role="execute",subs="attributes+"]
----
curl -s -u {mta_admin_username}:{mta_admin_password} {mta_ui_internal_url}/hub/rulesets | python3 -c "
import json, sys
data = json.load(sys.stdin)
print(f'登録済みルールセット数: {len(data)}')
for rs in data[:5]:

----

. 特定のルールセット (例: ID=1) の詳細を確認し、ルールの構造を見ていきます:
+
[source,bash,role="execute",subs="attributes+"]
----

----
+

=== ルールの YAML 構造を理解する

MTA のカスタムルールは YAML 形式で記述します。基本的な構造を確認します。標準的なルールの例を見てみましょう:

[source,yaml]
----
- ruleID: java-spring-boot-application-annotation
  labels:
    - konveyor.io/source=springboot
    - konveyor.io/target=custom-springboot-rule
  message: |-
    `@SpringBootApplication` は Spring Boot 専用です。Quarkus では多くの場合起動クラスごと不要です。
    詳細: https://quarkus.io/guides/lifecycle
  tag:
    - SpringBoot
    - Quarkus
  when:
    java.referenced:
      pattern: org.springframework.boot.autoconfigure.SpringBootApplication
      location: ANNOTATION
----

各フィールドの役割を確認します:

[source,text]
----
ruleID   : ルールの一意識別子 (プレフィックスで分類すると管理しやすい)
labels   : 変換元/変換先のテクノロジーラベル
message  : 検出時に IDE / レポートに表示されるメッセージ
tag      : 検出結果を分類するタグ (フィルタリングに使用)
when     : 検出条件 (java.referenced / xml / filecontent など)
----

=== よく使う `when` 条件のパターン

[source,yaml]
----
# Java クラス・アノテーションを検出
when:
  java.referenced:
    pattern: org.springframework.stereotype.Controller
    location: ANNOTATION

# pom.xml の要素を検出
when:
  builtin.xml:
    xpath: /m:project/m:parent[m:artifactId='spring-boot-starter-parent']
    namespaces:
      m: http://maven.apache.org/POM/4.0.0
    filepaths:
      - pom.xml

# ファイル内の文字列パターンを検出
when:
  filecontent:
    pattern: "SpringApplication\\.run"
    filePattern: "*.java"
----

=== 確認

ルール構造を理解できたか確認します。次のコマンドを実行し、組み込みルールセットを一覧します:

[source,bash,role="execute",subs="attributes+"]
----
curl -s -u {mta_admin_username}:{mta_admin_password} {mta_ui_internal_url}/hub/rulesets | python3 -c "
import json, sys
data = json.load(sys.stdin)
print('取得したルールセット数:', len(data))
print()
print('各ルールセットの名前:')
for rs in data:
    name = rs.get('name', '名前なし')
    rs_id = rs.get('id', '?')
    print(f'  ID={rs_id}: {name}')
"
----

ルールセットの一覧が表示されれば、ルールエンジンへのアクセスは正常です。

== エクササイズ 2: カスタムルールの作成

PetClinic の Spring Boot → Quarkus 移行では、次の 4 点が特に重要です:

* 起動クラス: `@SpringBootApplication`
* Web 層: `@Controller` (Spring MVC → JAX-RS)
* HTTP マッピング: `@GetMapping` など
* データ層: `JpaRepository` (→ Panache)

これらを検出するカスタムルールセットを YAML で作成します。

=== 前提条件

* 「環境の準備」で spring-petclinic のワークスペースが起動していること
* エクササイズ 1 で MTA ルールの構造を理解していること
* Dev Spaces のターミナルが開いていること

=== カスタムルールファイルの作成

. 作業ディレクトリに移動し、カスタムルール用ディレクトリを作成します:
+
[source,bash,role="execute"]
----
mkdir -p /projects/spring-petclinic/custom-rules
cd /projects/spring-petclinic/custom-rules
----

. PetClinic 向け Spring Boot → Quarkus カスタムルールファイルを作成します:
+
[source,bash,role="execute"]
----
cat > /projects/spring-petclinic/custom-rules/spring-to-quarkus-rules.yaml << 'EOF'
- ruleID: java-spring-boot-application-annotation
  category: mandatory
  effort: 2
  labels:
    - konveyor.io/source=springboot
    - konveyor.io/target=custom-springboot-rule
  description: "@SpringBootApplication は Quarkus では不要です。"
  message: |-
    `@SpringBootApplication` は Spring Boot 専用です。Quarkus では次のように整理します。

    1. 多くの場合は起動クラスごと削除し、CDI + `application.properties` だけで動かす
    2. 明示的な `main` が必要なら `@QuarkusMain` と `Quarkus.run(...)` を使う
    3. `SpringApplication.run(...)` は削除する
  tag:
    - SpringBoot
    - Application
    - Migration-Required
  when:
    java.referenced:
      pattern: org.springframework.boot.autoconfigure.SpringBootApplication
      location: ANNOTATION

- ruleID: java-spring-mvc-controller-to-jaxrs
  category: mandatory
  effort: 5
  labels:
    - konveyor.io/source=springboot
    - konveyor.io/target=custom-springboot-rule
  description: "@Controller (Spring MVC) を JAX-RS リソースクラスに変換してください。"
  message: |-
    `@Controller` は Spring MVC 用です。Quarkus では JAX-RS リソースとして定義します。

    1. クラスに `@Path("/...")` と `@ApplicationScoped` を付与
    2. メソッドに `@GET` / `@POST` などを付与
    3. Thymeleaf 連携は Qute (`TemplateInstance`) へ移行

    影響例 (PetClinic): OwnerController, PetController, VisitController, VetController
  tag:
    - SpringMVC
    - JAX-RS
    - Migration-Required
  when:
    java.referenced:
      pattern: org.springframework.stereotype.Controller
      location: ANNOTATION

- ruleID: java-spring-getmapping-to-jaxrs-get
  category: mandatory
  effort: 3
  labels:
    - konveyor.io/source=springboot
    - konveyor.io/target=custom-springboot-rule
  description: Spring MVC の @GetMapping 等を JAX-RS の @GET @Path 等へ置き換える
  message: |-
    Spring MVC の HTTP マッピングを JAX-RS に置き換えます。

    1. `@GetMapping("x")` → `@GET` + `@Path("x")`
    2. `@PostMapping` → `@POST` + `@Path` (同様に Put / Delete)
    3. 戻り値は論理ビュー名 (String) ではなく `TemplateInstance` または `Response`
  tag:
    - SpringMVC
    - JAX-RS
    - Migration-Required
  when:
    java.referenced:
      pattern: org.springframework.web.bind.annotation.GetMapping
      location: ANNOTATION

- ruleID: java-spring-jpa-repository-to-panache
  category: mandatory
  effort: 4
  labels:
    - konveyor.io/source=springboot
    - konveyor.io/target=custom-springboot-rule
  description: JpaRepository インターフェースを Quarkus Panache に変換してください。
  message: |-
    `JpaRepository<Entity, Id>` は Spring Data のインターフェースです。

    1. `@ApplicationScoped` なクラスで `PanacheRepositoryBase<Entity, Id>` を実装する
    2. ID 型はエンティティの `@Id` に合わせる (PetClinic は `Integer` が多い)
    3. `repository.save(...)` は `persist(...)` / `persistAndFlush(...)` に置き換える

    影響例: OwnerRepository, PetTypeRepository, VetRepository
  tag:
    - SpringData
    - Panache
    - Migration-Required
  when:
    java.referenced:
      pattern: org.springframework.data.jpa.repository.JpaRepository
      location: IMPORT
EOF
----

. 作成したルールファイルを確認します:
+
[source,bash,role="execute"]
----
cat /projects/spring-petclinic/custom-rules/spring-to-quarkus-rules.yaml
----

. コンテナイメージには PyYAML が入っていないため、先にインストールします:
+
[source,bash,role="execute"]
----
python3 -m pip install --user pyyaml
----
+
`Successfully installed` または `Requirement already satisfied` と表示されれば完了です。

. YAML の構文が正しいことを確認します:
+
[source,bash,role="execute"]
----
python3 << 'PY'
import sys
import site
from pathlib import Path

# Dev Spaces では user site が sys.path に入らないことがある
user_site = site.getusersitepackages()
if user_site not in sys.path:
    sys.path.insert(0, user_site)

import yaml

with open(Path("/projects/spring-petclinic/custom-rules/spring-to-quarkus-rules.yaml")) as f:
    rules = yaml.safe_load(f)

print("ルール数:", len(rules))
for r in rules:
    print("  - {}: タグ {}".format(r["ruleID"], r.get("tag", [])))
PY
----
+
4 件のルールが表示されれば、YAML 構文は正しいです。

== エクササイズ 3: ローカルルールをプラグインに追加して解析する

このエクササイズでは **Hub へのアップロードは使いません**。
プロジェクト内に作った YAML を、Dev Spaces の MTA プラグイン（Analysis Profile）へ追加して解析します。

[IMPORTANT]
====
ルールファイルは **ワークスペース内**（`/projects/spring-petclinic/custom-rules/`）に置きます。
ホーム配下（`~/...`）だと Explorer / Set rules のファイル選択から外れやすく、
OUTPUT ログにも `--rules` が載らない原因になります。
====

=== プロファイルへカスタムルールを追加する

. Dev Spaces で `/projects/spring-petclinic` が開いていることを確認します:
+
[source,bash,role="execute"]
----
cd /projects/spring-petclinic
pwd
ls custom-rules/spring-to-quarkus-rules.yaml pom.xml
----

. コマンドパレット (`Ctrl+Shift+P`) で `MTA: Open Analysis View` を実行します。

. Analysis View の設定（歯車 / Get Ready to Analyze）を開き、次でプロファイルを作成または更新します:
+
[source,text]
----
Profile Name: petclinic-custom-springboot-rule
Configure label selector (Target):
  - custom-springboot-rule    ← 候補に無ければ手入力で追加
Source:
  - （未指定で可）
Set rules:
  - Use Default Rules: オフ（カスタムだけ確認するなら推奨）
  - Custom rules: custom-rules/spring-to-quarkus-rules.yaml を選択（またはアップロード）
----
+
[NOTE]
====
Target に組み込みの `quarkus` ではなく `custom-springboot-rule` を使うのは、
標準ルールとラベルが被ると Issues / ログ上で区別しづらいためです。
YAML 側の `konveyor.io/target=` と **同じ文字列** である必要があります。
====

. 設定を閉じ、プロファイル `petclinic-custom-springboot-rule` が選択されていることを確認します。

. Analysis View の `Start` でサーバーを起動し、Running になることを確認します。

. `MTA: Run Analysis`（または Analysis View の Run Analysis）を実行します。完了まで 1〜3 分ほどかかります。

=== OUTPUT ログで「ルールが呼ばれたか」を確認する

Issues の前に、**OUTPUT（MTA / analyzer）** でカスタムルールが解析パイプラインに乗ったかを見ます。

. *View* → *Output* を開き、ドロップダウンで MTA / Konveyor / analyzer 関連チャネルを選びます。

. ログ内を次で検索します（`Ctrl+F`）:
+
[source,text]
----
custom-rules
spring-to-quarkus-rules.yaml
custom-springboot-rule
java-spring-boot-application-annotation
--rules
--label-selector
----

. 成功時の目安:
+
[source,text]
----
OK のサイン（環境により表記は多少異なる）:
  - 起動コマンドや設定に spring-to-quarkus-rules.yaml / custom-rules が含まれる
  - label-selector / target に custom-springboot-rule が含まれる
  - 上記 ruleID がロード／評価対象として出てくる

NG のサイン:
  - --rules や custom-rules パスが一切出ない → Set rules にファイルが載っていない
  - label-selector が quarkus のみ → カスタムラベルと不一致でフィルタ落ち
  - Use Default Rules のみで Custom rules 未選択
----

[TIP]
====
再実行してもログにパスが無い場合は、プロファイルを保存し直してから
Analysis View のサーバーを一度 Stop → Start し、再度 Run Analysis してください。
====

=== カスタムルールの検出結果を確認する（Issues）

. Analysis View / Developer Lightspeed のサイドパネルで Issues を開きます。

. 次の ruleID（または同等のメッセージ）が含まれることを確認します:
+
[source,text]
----
期待される検出結果:
  [java-spring-boot-application-annotation]  @SpringBootApplication
  [java-spring-mvc-controller-to-jaxrs]      @Controller
  [java-spring-getmapping-to-jaxrs-get]      @GetMapping
  [java-spring-jpa-repository-to-panache]    JpaRepository

任意で追加した `CustomRuleProbe.java` がある場合は、そのファイルへのヒットも確認できます。
  無くても PetClinic 本体（例: `*Application.java`, `*Controller.java`, `*Repository.java`）で検出されます。

. コマンドパレットで `Konveyor: View Issues` を実行し、同様の一覧が見えることも確認できます。

=== 確認

次がすべて満たされていれば、このモジュールの目標を達成しています:

* ルール YAML が `/projects/spring-petclinic/custom-rules/` にある
* Analysis Profile の Set rules にその YAML が選ばれている
* Label Selector の Target が `custom-springboot-rule` である
* OUTPUT にカスタムルールパス / ラベルの痕跡がある
* Issues に上記 4 系統の ruleID（または同等メッセージ）が見える

=== よくある問題

**問題**: 再実行しても OUTPUT にカスタムルールが現れない / 呼ばれていないように見える

→ **解決方法**:
. Explorer で `custom-rules/spring-to-quarkus-rules.yaml` が見えるか確認する（ワークスペース外だと不可）
. Get Ready to Analyze → **Set rules** で YAML が選択済みか確認する（Hub Target 登録では Plugin に同期されない）
. Label Selector が **`custom-springboot-rule`** か確認する（`quarkus` のままだとフィルタで落ちる）
. カスタムだけ見るなら **Use Default Rules をオフ** にする
. プロファイル保存後、RPC サーバーを Stop → Start してから再解析する

**問題**: カスタムルールの検出結果がゼロになる（ログにはパスがある）

→ **解決方法**:
. 分析対象が `/projects/spring-petclinic` か確認する
. YAML の `konveyor.io/target=` と Profile の Target 文字列が一致しているか確認する
. PetClinic 本体に `@SpringBootApplication` / `@Controller` 等があるか、エクササイズ 2 の grep で確認する

**問題**: Analysis View が Running にならない

→ **解決方法**: Module 1 / 2 と同様に `Start` を押し直し、Hub Configuration と GenAI 設定を確認します。
